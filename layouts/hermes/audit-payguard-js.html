The component library catalogued how this layout looks. This is the other half: 1,627 lines of behaviour, sorted into what was meant, what was meant and is wrong, and what was never finished.

Every finding below was checked against the file running in a browser, not read off the source. Where a claim is about what the code produces at runtime, the evidence block is the actual output.

The headline: the two features this layout leads with — the gauge and the trial-month tracker — are the two that do not work. Everything underneath them is sound.

Job and entry CRUD, with confirmaddJob · editJob · deleteJob · addEntry · editEntry · deleteEntry

Full lifecycle on both records, every mutation followed by saveState() then render(), deletes routed through confirmDialog. Deleting a job cascades to its entries. One state object, one save, one re-render — no diffing, no reconciliation, and at this data size it is instant.

Intentional and wrong Fix before reuse

Deliberate features, incorrect logic. These are the ones that would silently mislead a reader about their benefits, so they matter more than the count suggests.

The gauge compares a year to a monthrender() line 723

The headline number on the page. It totals every entry ever recorded and divides by the monthly limit.

const ytdTotal = state.jobs.reduce((s, j) => s + jobYTD(j), 0); const pct = clamp(ytdTotal / SGA_TRIAL, 0, 1); // SGA_TRIAL is $1,210 PER MONTH

The dial is pinned to full from the second month of any working year, and the big figure under it is a year total wearing a monthly label. A reader earning a safe $400 a month sees "over" by March.

FixThe gauge should measure this month against the monthly limit. That is the question the layout claims to answer.
Trial work period is not implementedcountTwpUsed()

The second most prominent feature. It counts distinct months containing any entry at all — no earnings threshold, no rolling window — then caps the answer at 9.

const months = new Set(); state.entries.forEach(e => { months.add(e.year + '-' + e.month); }); // Only count months within TWP window (last 9 months from now or starting point) return Math.min(sorted.length, TWP_TOTAL);

Three defects in six lines. A $5 entry burns a service month. The comment describes a window the code does not implement — the real rule is nine months inside a rolling sixty. And Math.min(…, 9) means the count can never exceed nine, so "you have used them all" is a state the tracker can reach but never pass, and never warn about.

SGA_SUBSTANTIAL ($1,690) exists and is never used in a calculation — it appears once, inside a sentence of explanatory copy.

FixNeeds the threshold test and the 60-month window. Until then the dots are decoration with a number next to them.
YTD is not year-to-datejobYTD()

filter(e => e.jobId === job.id && e.year <= todayMonth().year) — every year up to and including this one. The label on screen says YTD. Second year of use, the figure quietly becomes a lifetime total.

FixOne character: <= to ===. It feeds the gauge, the job cards and the ledger group headers.
Rename-on-blur throwsrenderJobCard() line 954

The inline name editor's blur handler takes no argument but reads one.

onBlur: () => { const v = e.target.value.trim(); // `e` is not defined in this scope ... }

Clicking away from a renamed job throws a ReferenceError and loses the edit. Only pressing Enter saves. The bug is invisible because the Enter path is the one anyone testing would use.

Gig income has no colour — the CSS rule is invalid.job-badge.1099 · renderJobCard line 929

The stylesheet declares .job-badge.1099, .job-badge.gig { … }. A CSS class cannot begin with an unescaped digit, so the selector is invalid — and an invalid selector in a comma list invalidates the entire rule, taking .gig down with it. The JS emits class="job-badge 1099", which matches nothing.

rules the browser actually parsed: .job-badge | .job-badge.w2 | .job-card.active .job-badge computed styles: "job-badge 1099" → background rgba(0,0,0,0) ← transparent "job-badge w2" → background rgb(219,234,254) ← blue, as intended

So W-2 is colour-coded and self-employment is not — the distinction that changes the arithmetic is the one that lost its badge.

FixRename the class. This also settles the --brand / --1099 token collision flagged in the component library.
Every select in the inline editor showed the wrong valueel() · the Type and Cycle selects

Both selects were built as el('select', { value: job.type }, [ …options ]). A <select> cannot take its value from an attribute, and it cannot take it before its options exist — and el() sets attributes first, then appends children.

So both dropdowns always displayed their first option. Every job read as "W-2 (counts in full)" and "Weekly" regardless of what was stored, while the card header directly above showed the truth — a panel disagreeing with its own header by two fields.

The Type one is the dangerous half. W-2 versus 1099 is the field that decides whether mileage comes off, and the editor was telling every gig worker their job counted in full.

before → Type: "W-2" Cycle: "weekly" (stored: 1099, biweekly) after → Type: "1099" Cycle: "biweekly" (stored: 1099, biweekly)

Fixed once in el(): after children are attached, a SELECT takes its value as a property. All eight fields of the expanded panel now match the stored job.

FixedOne place, and it covers every select in the file including any added later.

What this means for the ninth layout

The mining is worth it. Roughly two thirds of this file is sound, and the parts that are sound are the parts that are hard: entry, grouping, in-place editing, persistence that survives schema changes, navigation with no router.

Do not inherit the domain layer. Every SSA calculation here is either wrong (the gauge, the trial period, YTD) or thin (one deduction subtraction). The real app already has src/domain/ — rules.ts, trialWork.ts, capacity.ts — where these questions are answered properly and shared across eight layouts. Take the interface, wire it to the domain that already exists.

That split is the finding. The value in this file is interaction and structure; the danger is that it also contains confident-looking arithmetic about someone's benefits, and that arithmetic is the part to leave behind.

Method. Static reads for structure; a live browser for every runtime claim. Computed styles, parsed stylesheet rules, handler presence and function output were read out of the running page — the evidence blocks are that output, not a description of the source.
